# v0.1.4 — 2026-05-16 — **Final Phase 1**

Phase 1 complete. Ready for Phase 2.

## Critical Bug Fixes

### WireGuard Connectivity
- **Interface name too long**: `wg-proj-{uuid}` (16 chars) exceeded Linux `IFNAMSIZ=15`, causing `ip link add` to fail silently. Changed to `bn-{uuid}` (11 chars).
- **Key format mismatch**: Device public/private keys were stored as hex (64 chars), but `wg set` only accepts base64. Auto-conversion hex→base64 now applied in `AddPeer`/`RemovePeer`. Client stores keys as base64.
- **No auto-recovery**: `EnsureInterface()` called during each handshake — WireGuard interface auto-recreates if missing (e.g., after server reboot).
- **Allowed-IPs**: Fixed from `10.0.0.4/24` to `10.0.0.4/32` — eliminates "nonzero host part" warning and ensures correct routing.
- **Firewall**: Port 51820/udp was blocked by UFW — now opened.

### IP Allocation
- **Sequential → Random**: IP allocation changed from sequential (`2 + deviceCount`) to **random selection from all unused IPs** in the `/24` subnet. Avoids gaps from revoked devices and prevents collisions.
- Uses `ip_allocations` table for ground truth — revoked IPs are properly freed and available for reassignment.
